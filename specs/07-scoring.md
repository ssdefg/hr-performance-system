# 07. 평가 점수 계산 공식 및 엣지 케이스 규칙 (Scoring Engine & Rules)

## 1. 개요
본 문서는 HR 인사평가 시스템의 핵심 연산 엔진인 **개인 평가 점수 산출**, **가중치 검증**, **팀 보너스 합산**, **100점 상한 규칙(Cap Rule)** 및 발생 가능한 모든 **엣지 케이스(Edge Cases)**의 처리 기준을 정의합니다.

---

## 2. 수학적 계산 공식 및 정의

### 2.1 평가 항목 가중치 규칙
- 시스템에 등록된 활성 평가 항목 집합 $C = \{c_1, c_2, \dots, c_N\}$에 대해:
  $$\sum_{i=1}^{N} \text{weight}(c_i) = 100$$
- $\text{weight}(c_i)$는 양의 정수 ($1 \le \text{weight}(c_i) \le 100$)

### 2.2 개인 평가 점수 (Individual Raw Score)
- 각 평가 항목 $c_i$에 대해 매니저가 부여한 정수 척도 점수 $s_i \in \{1, 2, 3, 4, 5\}$
- 개인 점수 $S_{\text{raw}}$ 계산식:
  $$S_{\text{raw}} = \sum_{i=1}^{N} \left( \frac{s_i}{5} \times \text{weight}(c_i) \right)$$
- **소수점 처리**: 소수점 셋째 자리에서 반올림하여 **소수점 둘째 자리**까지 산출 및 저장 (예: $83.333\dots \rightarrow 83.33$).

### 2.3 팀 보너스 점수 (Team Bonus Score)
- 관리자가 특정 팀에 부여하는 보너스 $B_{\text{team}}$
- 허용 범위: $0.0 \le B_{\text{team}} \le 10.0$ (정수 또는 0.5 단위 소수점 지원)

### 2.4 최종 산출 점수 (Final Score) 및 상한 규칙 (Cap Rule)
- 최종 점수 $S_{\text{final}}$ 계산식:
  $$S_{\text{final}} = \min(100.00, \max(0.00, S_{\text{raw}} + B_{\text{team}}))$$
- **상한 플래그 (`is_capped`) 판정**:
  $$\text{is\_capped} = \begin{cases} \text{True}, & \text{if } (S_{\text{raw}} + B_{\text{team}}) > 100.00 \\ \text{False}, & \text{otherwise} \end{cases}$$

## 3. 엣지 케이스 및 예외 처리 규정

| 구분 | 상황 / 입력값 | 처리 방식 및 시스템 동작 |
| :--- | :--- | :--- |
| **가중치 합계 불일치** | 항목 가중치 총합이 100이 아님 (예: 95 또는 105) | - **매니저 평가 차단**: 매니저의 평가서 작성/제출 화면 진입 시 "가중치 합계가 100이 아니므로 평가를 진행할 수 없습니다" 경고창 표시 및 폼 비활성화<br>- **관리자 알림**: 관리자 대시보드 및 항목 관리 화면에 적색 경고 인디케이터 상시 노출 |
| **만점 + 보너스 상한** | 개인 점수 100점 + 팀 보너스 5점 | - 단순 합계는 105점이나, 최종 점수는 **100.00점**으로 확정 제한<br>- UI에 `(상한)` 캡슐 배지 표시 |
| **근접 만점 + 보너스 상한** | 개인 점수 97점 + 팀 보너스 5점 | - 단순 합계 102점 $\rightarrow$ 최종 점수 **100.00점** 확정, `(상한)` 배지 표시 |
| **보너스 점수 유효성 위반** | 보너스 점수로 음수(-1) 또는 10점 초과(15) 입력 | - API 단에서 `400 Bad Request` 반환 (`"보너스 점수는 0.0점에서 10.0점 사이여야 합니다."`)<br>- 프론트엔드 인풋 필드에 min=0, max=10, step=0.5 제한 |
| **미제출자 점수 처리** | 매니저가 아직 제출하지 않은 평가 대상자 | - 개인 점수 및 최종 점수: `null` 또는 계산 보류 처리<br>- 통계(전사 평균) 산출 시 모수에서 제외<br>- 점수 테이블에 `평가 대기` 배지 표시 |
| **팀 보너스 변경 시 일괄 재계산** | 관리자가 팀 보너스를 기존 3점에서 5점으로 변경 | - 해당 팀 소속 모든 직원의 $S_{\text{final}}$ 및 `is_capped` 상태가 트랜잭션 내에서 일괄 갱신됨 |

## 4. 계산 예시 시나리오

### 시나리오 A: 일반적인 평가 결과
- 가중치: 기획력(40), 실행력(40), 팀워크(20) [합계 = 100]
- 매니저 채점: 기획력 4점, 실행력 5점, 팀워크 3점
- 개인 점수: $(4/5 \times 40) + (5/5 \times 40) + (3/5 \times 20) = 32 + 40 + 12 = 84.00\text{점}$
- 소속팀 보너스: $+3.5\text{점}$
- 최종 점수: $\min(100.00, 84.00 + 3.5) = \mathbf{87.50\text{점}}$ (`is_capped = False`)

### 시나리오 B: 상한선 초과 케이스
- 가중치: 역량(50), 성과(50) [합계 = 100]
- 매니저 채점: 역량 5점, 성과 5점
- 개인 점수: $(5/5 \times 50) + (5/5 \times 50) = 100.00\text{점}$
- 소속팀 보너스: $+5.0\text{점}$
- 최종 점수: $\min(100.00, 100.00 + 5.0) = \mathbf{100.00\text{점}}$ (`is_capped = True`, UI에 `(상한)` 뱃지 표시)
